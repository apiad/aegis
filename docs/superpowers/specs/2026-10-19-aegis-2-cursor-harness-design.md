# Cursor sessions in aegis 2

> **Status:** implemented 2026-10-19, on
> [#488](https://github.com/apiad/aegis/issues/488).
> Model harness: `2026-10-08-aegis-2-opencode-harness-design.md` (the contract)
> and `src/aegis/codex/` (the closest implementation: a JSON-RPC child on stdio).
> Every number below was measured on cursor-agent 2026.10.14 on 2026-10-19; the
> raw probes live in `/tmp/opencode/cursor-probe/`.

An agent whose harness is `cursor` spawns from the new tab and behaves like a
Claude session. Its transcript streams token by token, with the same glyphs and
tool rows. It takes prompts, interrupts, slash commands and inbox messages, and
it resumes after a server restart. Its model and permission mode change while it
runs. It calls every aegis tool over MCP and can be a queue worker.

Two things Cursor gives no other harness: titles generated by the harness
(`session_info_update` carries one), and permission modes that are read-only by
construction. Two things it does not give, and aegis therefore cannot show:
**cost** and **token counts** — neither interface reports either.

## What Cursor does

`cursor-agent` is a Node bundle (`/opt/cursor-agent/index.js`, 105 chunks) with
several interfaces. Two are driveable:

1. **`cursor-agent acp`** — a hidden command ("Start the Cursor Agent as an ACP
   (Agent Client Protocol) server", absent from `--help`'s Commands but parsing
   its own `--help`). Newline-delimited JSON-RPC 2.0 on stdio. One process, many
   sessions.
2. **`cursor-agent -p --output-format stream-json --stream-partial-output`** —
   one turn per process, with `--resume <sessionId>` to continue a chat.

Measured behaviour of `acp`:

| Question | Answer |
|---|---|
| `initialize` | ok: `protocolVersion 1`, `agentCapabilities {loadSession, mcpCapabilities {http, sse}, promptCapabilities {image}, sessionCapabilities {list}}`, `authMethods [cursor_login]`. ~8 s to first response |
| `clientCapabilities.terminal` | a boolean; an object is rejected |
| `session/new` | `mcpServers` is **required** (an array, `[]` allowed). Accepts `{name, type: "http", url, headers: [{name, value}]}` |
| `session/new` result | `{sessionId, configOptions, models, modes}` — 46 models with ids that carry their overrides (`claude-opus-5[thinking=true,context=300k,effort=high,fast=false]`), modes `agent` / `plan` / `ask` |
| `session/load` | restarts a session in a new process: same conversation, modes and models again. Its answer is `session/new`'s keys **minus `sessionId`** — the id asked for keeps the conversation — and before the answer the conversation replays as whole-text chunks (one user, thought and message chunk in a measured turn) |
| `session/prompt` | `{stopReason: "end_turn"}`; streams `session/update` notifications meanwhile |
| `session/set_model` | works with those ids; a bad id is `-32602 Invalid model value: …` |
| `session/set_mode` | works (`agent`, `plan`, `ask`) |
| `session/cancel` | **`-32601 Method not found`** — the method is in the bundled ACP schema, the server does not implement it |
| `session/request_permission` | **sent** when a call falls outside the allowlist (measured later: `Not in allowlist: cat` in stderr, then the request; the first reading of "never" was that a file write and `ls` in `agent` mode get none, which is what the allowlist covers). Four options: allow once, allow always, reject once, reject always |
| usage and cost | **none**: no `token_count` update in any turn, and Cursor's `-p` result carries tokens (`usage {inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens}`) but no cost, in either output format |
| `session/list_models` | not found; the catalog is what `session/new` and `session/load` return |

Permissions, measured by asking for a file to be created:

| Interface | Effect on writes |
|---|---|
| `-p`, no flag | writes allowed |
| `-p --mode plan` | refused |
| `-p --mode ask` | refused |
| `-p -f` / `--yolo` | allowed |
| `CURSOR_CONFIG_DIR=<dir>` with `cli-config.json` `{"permissions": {"deny": ["Shell(*)"]}}` | **shell blocked** (the model answered `NO_SHELL`), everything else unchanged |

That last row is the only per-process permission knob Cursor offers, and aegis
does **not** use it: it is process-wide, so two sessions of one agent could not
differ, and permission is enforced per request instead (below). The same
directory does **not** move `mcp.json` — `mcp list` still reports "expected in
`.cursor/mcp.json` or `~/.cursor/mcp.json`" — so MCP cannot be injected that way.

MCP over ACP was verified against a local fastmcp server named `aegis` with one
tool: `session/new` accepted it, the tool was called, and Cursor showed it to the
model under its **bare name** (`meta`), titled `aegis: meta` in the tool row.
There is no server prefix.

The system prompt has no channel:

| Tried | Result |
|---|---|
| `cursor-agent acp --system-prompt <file>` | the parser accepts the flag and the ACP driver ignores it: the model did not follow an instruction the file contained |
| `--system-prompt <text>` | "Error: --system-prompt file not found: …" — it takes a path, not text |
| `--system-prompt <file>` with `-p` | the turn failed twice with "Connection lost, reconnecting" while the same turn without the flag succeeded |
| `systemPrompt` in `session/new` | accepted, ignored |
| `CURSOR_HARNESS_PROMPT_ID` / `_CATEGORY` | telemetry labels (`harness_test_name`, `harness_prompt_category`) — no prompt is read from them |
| `.cursor/rules/*.mdc` with `alwaysApply: true` in the workspace | **works**, in ACP and in `-p` alike — but one file per workspace, so concurrent sessions of different agents would share it, and aegis would have to write into the user's tree |

## The fork, and why ACP

| | `acp` (one process per session) | `-p --resume` (one process per turn) |
|---|---|---|
| aegis MCP per session | ✅ `session/new.mcpServers` carries the URL and the session token as a header | ❌ no injection point: MCP config is read from fixed paths |
| streaming, tools, title | ✅ chunks, `tool_call`, generated title | ⚠ deltas and tool events, no title |
| token counts for the card | ❌ none | ✅ per turn |
| model change mid-run | ✅ `session/set_mode` and `set_model` | only between turns |
| permission levels | ✅ `plan` / `ask` / `agent`, with each `session/request_permission` answered per level | ⚠ flags only |
| interrupt | kill the process, `session/load` to continue | kill the process |
| resume after restart | ✅ `session/load` | ✅ `--resume <id>` |
| start cost | ~8 s once per session | every turn |

The aegis MCP server is not optional: an agent without it has no `turn_end`, no
monitors, no queues and no handoffs. Only ACP can hand a session its own token,
so ACP is the driver, and the token counts `-p` would have given are the price.

## The design

`src/aegis/cursor/` mirrors `src/aegis/codex/`: `harness.py` (the `Harness`
implementation and `build_argv`), `process.py` (the ACP child), `stream.py` (raw
ACP messages to transcript events), `config.py` (the catalog and the probe).

**Start** — spawn `cursor-agent acp --trust` on stdio, in the session's cwd, with
no config directory of its own (measured as a way to deny the shell, rejected:
it is process-wide, and permission is answered per request instead). Send
`initialize`, `notifications/initialized`, then `session/new` with
`mcpServers: [{name: "aegis", type: "http", url, headers: [{name:
"X-Aegis-Session", value: token}]}]`. The `sessionId` is what the session keeps
for a restart — and a resume keeps the id it asked for: `session/load` answers
the same keys as `session/new` minus `sessionId` (measured). The conversation
it re-announces before its answer is caught in the driver and not folded
again: the store already holds those lines, and the command catalog inside the
replay is still read.

**The primer** — Cursor has no system-prompt channel (measured above), so the
primer and the priming go at the front of the session's first prompt, exactly the
two strings Claude gets through `--append-system-prompt`. The echoed `user`
message the harness writes to the store carries only the person's own text, so
the transcript stays clean.

**Send** — `session/prompt {sessionId, prompt: [{type: "text", text}]}`, one raw
ACP message per store line, until `stopReason` arrives. A second
`session/prompt` mid-turn **cancels** the one running (measured), so nothing
like Codex's steers: aegis queues the prompt in the driver and reads it when the
turn ends, as the next turn.

**Interrupt** — `session/cancel` does not exist, so the turn is closed from the
driver: `aegis/turn_done {stop_reason: "interrupted"}` is emitted first (the
Session records the interrupt before the kill, so the entry order holds), the
queued prompts are cleared, and the child is ended quietly, its exit not
reported again. The next prompt starts a fresh child and resumes with
`session/load`.

**set** — `model` and `effort` become one `session/set_model`: the catalog's ids
carry their own `effort=`/`reasoning_effort=` overrides, and `set_model` takes
only the exact id, so a model's effort is rewritten in place and an effort the
id does not carry raises `ControlError`, the same rule as Claude. `permission`
becomes `session/set_mode`, and every `session/request_permission` is answered
at the level: `read` rejects, `write` allows anything but a shell, `auto` and
`full` allow all — never "allow always", so the decision stays aegis's, per
turn.

**Catalog and probe** — `session/new` (or `session/load`) answers with the models
and modes, so `catalog()` reads the session's own answer, and `probe()` opens a
throwaway session to read it. `cursor-agent models` exists (265 ids, `id -
Label`, one line each) but is deliberately **not** used: its ids are not the
ones `set_model` accepts (measured: a bare id is `-32602 Invalid model value`).

### Parser

Raw ACP messages become transcript events as:

| ACP | aegis event |
|---|---|
| `session_info_update` | a Title event — the card's title |
| `agent_thought_chunk` | a Thinking event carrying the block's text so far, keyed |
| `agent_message_chunk` | a Text event carrying the block's text so far, keyed |
| `tool_call` | a tool entry, pending, from `title` and `kind` (`read`, `edit`, `execute`, `search`, `fetch`, `other`) |
| `tool_call_update` | the same entry's status and output: `content` (a diff for writes) and `rawOutput` `{exitCode, stdout, stderr}` for the rest (measured from the bundle's `presentCompletedToolCall`) |
| `available_commands_update` | the slash-command catalog, read by the process; the fold draws nothing |
| anything else | Ignored and drawn by nothing — the line itself stays in the store, so a new kind can be read there |

The chunk rows are the one place Cursor diverges from every other harness: no
update of its own ever repeats a block, so the chunk lines **are** the store's
copy (each carries the text so far), and a fresh fold rebuilds exactly what
streamed.

### Permissions

| aegis | Cursor |
|---|---|
| `read` | `session/set_mode plan`, every request rejected |
| `write` | `agent`, requests allowed except a shell |
| `auto` | `agent`, every request allowed |
| `full` | `agent`, every request allowed |

The order stays monotone: `read` is the only one that loses power, and no level
reaches power it did not ask for. `agent` mode approves file work without asking
(measured), but a shell outside the allowlist does raise
`session/request_permission` — the first probe's "never sent" was that turn's
file write and `ls`, which `agent` mode allows — and the driver answers it at
the level, never "allow always", so `auto` and `full` still behave alike and
the decision stays aegis's.

## Testing

`tests/fake_cursor.py` is a real ACP server over stdio: it answers
`initialize`, `session/new` with models and modes, and a prompt with the same
events Cursor sends, including a tool call and a title. The tests then run the
real app, as the fake Claude and fake Codex do:

- one session spawns, streams its events and ends on `stopReason`, and the
  recorded turn fixture (`tests/fixtures/cursor/acp-turn.jsonl`, 35 lines of a
  real turn) folds back into the same entries;
- `set_model` and `set_mode` reach the child and change its answer, and the
  model catalog and command list come from the child's own answers;
- permission requests are answered per level, and "allow always" is never the
  answer;
- an effort the model id does not carry raises `ControlError`, and an unknown
  model id is refused the way Cursor refuses it;
- a prompt typed mid-turn waits and becomes the next turn, not a cancel;
- killing the process ends the turn as interrupted, and `session/load` resumes
  it with the same conversation while its replayed history adds neither an
  entry nor a store line, and the session id stands although the load answer
  omits it;
- the MCP config the session builds carries its token as the header;
- `doctor` finds an installed cursor, probes its version and catalog, and
  `make test-live` drives a real `cursor-agent` on a logged-in machine.

## Out of scope

- Cost and token counts: Cursor reports neither through ACP. The card shows no
  cost and no context gauge for these sessions, and the help page says so.
- `session/cancel`: until Cursor implements it, an interrupt kills the process.
- An approval card for `session/request_permission`: requests are answered by
  the level's policy at once — a card would ask the person to decide what the
  level already decides, and "allow always" is never the answer.
- `.cursor/rules` as the primer channel: it would work, but aegis would write
  into the user's tree and concurrent sessions would share one file.
- Cursor's IDE, cloud agents, and quota lines for its subscription.

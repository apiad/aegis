# aegis2 slice 3 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status: in progress, 2026-10-06.** Executed inline by the session that wrote it.

**Goal:** agents in aegis2 get monitors, queues, handoff, peer read, session list,
rename and meta over MCP, with an inbox delivering what those produce.

**Architecture:** Registry operations marked for agents are projected as fastmcp
tools at `/mcp`; the caller comes from a per-spawn token header. Sessions get an
inbox that holds messages during a turn. Monitors and queues are managers owned by
the app, persisted under the state root.

**Tech Stack:** as before; fastmcp 3.2 (already a dependency).

**Spec:** `docs/superpowers/specs/2026-10-06-aegis2-slice-3-design.md`

## Global Constraints

- Tool name = operation name with `.` replaced by `_`; server name `aegis`.
- No `from_handle` parameter on any operation.
- Header `X-Aegis2-Session`; an unknown token is refused.
- Inbox header format `> from <kind>:<name> · <detail> · <ISO ts>`.
- Monitor defaults: `interval_s=10`, `timeout_s=3600`; each condition limited to 30 s.
- Finished worker = turn ended and no live monitor, no held message, no open Claude task.

## Review Focus

1. A worker that arms a monitor and ends its turn is not completed, and is when the monitor's wake ends its next turn with nothing pending. Task 5.
2. Two messages arriving mid-turn reach the agent once each, in order, in one turn. Task 2.
3. A restart with a running task, a live monitor and a held message: all three survive. Tasks 3, 4, 5.
4. An agent cancelling another session's monitor or task is refused. Tasks 4, 5.
5. A stopped session receiving a monitor wake resumes and gets it. Task 4.

---

### Task 1: Caller identity, agent operations, the MCP endpoint, the primer
- `ops.py`: `Registry.op(name, params, agent=False, doc="")`; handlers take `(params, caller)`; `Caller(kind: "user"|"agent", log_id: str | None)`.
- `mcp.py`: `build_mcp(app) -> (FastMCP, asgi_app)`; one tool per agent op with the params' schema; token resolution; `primer(session) -> str`.
- `session.py`: a token per process start; `--mcp-config` and `--append-system-prompt` in the argv.
- `web.py`: mount `/mcp`, run its lifespan.
- Fake claude: `/mcp <tool> <json>`.
- Tests: tools listed with the right names and schemas; no token or a wrong one refused; a valid one acts as its session; the argv carries the config and primer.

### Task 2: The inbox
- `session.py`: `deliver(header, body)`; held messages in the meta; flush on turn end; resume when stopped.
- `entries.py`: `inbox` kind.
- Tests: idle delivers at once; working holds and batches; stopped resumes; held survive a restart; archived refuses.

### Task 3: Small tools
- `peer.handoff`, `peer.read`, `session.list`, `session.rename` (own), `meta`.
- Tests through the endpoint with the fake.

### Task 4: Monitors
- `monitors.py`: `Monitors(app, path)`: start, cancel, list, persistence, the poll loop with `asyncio.create_subprocess_exec("bash","-c",…)`, wake through the inbox; progress in the meta.
- Tests: done, fail, timeout, progress; other live monitors listed in the wake; cancel own only; survives restart; a wake resumes a stopped owner.

### Task 5: Queues
- `queues.py`: config, `tasks.jsonl`, enqueue, dispatch, the completion rule (turn-end hook plus open Claude tasks from notices), callback, cancel, resume, boot replay with auto-resume.
- `stream.py`: `Notice` carries `task_id`, `status`, `backgrounded`.
- Tests: completion waits for a monitor, a held message, an open Claude task; callback content; failure on exit; parallel limit; restart resumes a running task.

### Task 6: Client
- Inbox and aegis-tool rows; sidebar monitors; card monitor count and worker badge.
- Browser test: a monitor armed through the fake shows in the sidebar and its wake arrives as an inbox row.

### Task 7: Live test, docs, PR
- Live: real Haiku arms a monitor on a file and is woken.
- DESIGN.md, spec status, changelog; `make check`, PR, CI, merge.

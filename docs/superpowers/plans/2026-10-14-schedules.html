Schedules: implementation plan

The work for issue #390 in two pull requests. The first adds the engine: the clock, the four layers, the run log, the watcher and the close rule, the nine schedule_* operations and their tools. The second adds the #schedules view and its editor. Every block of code below was run before this plan was written: it comes from a prototype on a copy of main, and each task says which tests passed there.

specdocs/superpowers/specs/2026-10-14-schedules-design.html. Executors read both. goalA person or an agent creates a schedule that fires a prompt on a clock, gated by overlap and an optional bash check, into a new session or an existing one; runs close themselves by their last turn_end; a view shows and edits every schedule. architectureFour new modules. clock.py parses every, cron and at and finds ticks. schedule_log.py holds the definitions (pydantic) and folds the run log, with no server around it. schedules.py is the engine, one object on the app with a clock task. schedule_ops.py registers the operations. Global constraints

  • Use uv, never pip. Add no dependency: the cron parser is aegis's own.
  • Values, verbatim from the spec: the smallest every is 1m; a check's timeout defaults to 30 s and is at most 300 s; the check's stdout is cut at 8 KB; 3 errors in a row pause; the clock task wakes at least once a minute; a finished at is deleted after 7 days; compaction keeps the last 100 fires; the cron search walks at most 366 days.
  • The header is > from schedule:<name> · run#<n> · tick <HH:MM>, and a schedule's name is a session handle's shape (names.valid_handle).
  • Ticks and anchors are whole seconds. A tick written to the log and read back must be the same number, or an every fires twice after a restart.
  • Schedules live in <state>/schedules.json and <state>/schedule-runs.jsonl. Nothing goes in .aegis.yaml.
  • Boot reads meta files, never stores (DESIGN.md). The new schedule session field goes in Session.__init__, Session.meta() and Registry._session.
  • Client: every CSS rule is scoped under #a2; people's and agents' text is set with textContent, never innerHTML; no confirm, alert or prompt; the view's key is an action in keys.js.
  • A test that runs over 3 s without @pytest.mark.slow fails the fast lane. In the prototype the slowest engine test took 2.2 s.
  • The repo is public: no personal names, machines or accounts in code, docs, commits or PR bodies. Sample principals are ana, ben, cara.
  • Commits: conventional, English, one per task, git commit -- <paths>, never amend, never git add -A. Run make format-check before pushing; make check reformats silently.
  • Prose in docstrings, the help page, DESIGN.md and the changelog follows the workspace's unslop rules.

Review focus

  • A check whose command is missing exits 127 on every tick. It must count as an error and pause the schedule after three, with the shell's "not found" line in the toast, never read as a quiet "not yet".task 5, test_a_missing_command_is_an_error_not_a_quiet_tick
  • A person closes a run's tab while it works. The run must end, and a tick held for it must fire, instead of the schedule waiting forever on a session that is gone.task 5, test_a_run_whose_tab_a_person_closes_ends_and_lets_a_held_tick_go
  • The machine sleeps eight hours through an every-5-minute schedule. It must fire once on waking, logged as 96 missed ticks, not 96 times.task 5, test_a_machine_that_slept_eight_hours_fires_once
  • A schedule is deleted while its run works. The run keeps going and its session stays open; finishing it must not raise for a schedule that no longer exists.task 6, test_a_schedule_deleted_mid_run_leaves_its_run_alone
  • The target of an existing-session schedule is renamed. The schedule must keep firing into it, so it is stored by log id, not by handle.task 5, test_a_renamed_target_still_gets_its_fires

Where this plan departs from the spec

  • The shared finish rule is Registry.finished, a method, not a function finished(s, monitors, registry). The registry already holds the monitors and the sessions whose children it counts (Registry._waits, registry.py).
  • A queue worker that started a session now finishes when that session stops working. The spec says workers have no children, but nothing stops a worker from calling session_spawn, and Queues.finished now delegates to the shared rule.
  • The spawn refusal sits in ops.Registry.call (ops.py), through a schedule_of hook the app sets beside permission_of. The spec's "Registry.call" is this one.
  • A new fire stores its working directory as fire.cwd, filled at creation with the creator's directory, because agents in .aegis.yaml have none and agents.resolve needs one.
  • An existing target is stored by log id; a handle is accepted when the schedule is created or edited.
  • A tick record carries tick, the tick's own time in whole seconds, beside t, when it was logged. Folding an every needs the exact tick.
  • A missed tick is two records: one with out: "missed" and n, then the record of what the layers did with it.
  • Resuming a paused schedule starts its clock from now. The ticks that fell during the pause are not missed ticks. The spec says nothing on this.
  • The schedule: header needs no parser change: transcript/entries.py already folds any line starting > from into an inbox row. The primer and the fake claude learn it.
  • schedule.test takes a loose form (clock, check, session, cwd, name) and answers a clock that does not parse with {"error": ...} instead of bad_params, so the editor shows one readable line.
  • schedule.runs returns rows the table draws (schedule_log.rows): a fire joined with its end, quiet stretches merged on the server. Compaction at boot merges them in the file too.
  • No command-line subcommand. The spec says the command line can use schedules; aegis has no CLI for queues or monitors either. People use the view, agents the tools.
  • The view's key is Alt+K, the first Alt chord free in keys.js. The spec names none.
  • Delete asks for a second click instead of a dialog, as the client's rule against confirm requires.
  • The engine's code lands whole in task 5. Its layers share one pass, so splitting it by layer would leave half a pass untestable; task 5's tests pin every behaviour the spec lists for the engine.

How the work divides

Eight tasks, no split point. Tasks 1 to 4 are the deferred items, each independent of the others. Tasks 5 and 6 are Settings → Workflows, server then browser. Task 7 is the recipes page and the system-prompt line. Task 8 is the docs and the full gates; it ends where the smoke test and the release begin.

Global constraints

  • Person-only stays person-only: workflow.read is not marked for agents (no MCP tool reaches it), and the Settings section is drawn for admins only. Its test fails if the op is marked agent=True.
  • Help anchors come from aegis.helppages.slug(): print a heading's slug before linking to it. A backticked word with an underscore on a help page is read as a tool name by tests/test_help_pages.py and by rift, so a field such as at_max or max_agents is written bare or inside a YAML block, never backticked alone (`max_agents:` with its colon is a config key, which is fine). Rift requires every agent tool on a help page; this slice adds none.
  • tests/test_help_index.py pins questions to sections. A new recipe that takes an existing pin's first place is reworded; the pin never is.
  • Client CSS sits under #a2; run make site-css after changing client/css. Every new part fits a 390 px window.
  • A test that starts a real server and takes more than 3 s, and every browser test, is marked @pytest.mark.slow; make check fails an unmarked test over 3 s.
  • Commits: conventional, English, one per task, git commit -m … -- <paths>; never git add -A, never amend. The repo is public: name no person, machine or company. Sample names are ana, ben and cara; sample sites are example.com.

Review focus

  1. An agent reaching a person's operation: workflow.read has no tool; an import is the person's save, and the save lints on the server whatever the browser did. task 6
  2. A workflows: block lost by a Settings save: an untouched block is written as it was, a block that does not parse is kept, and only an emptied pool removes it. task 5
  3. The args check refusing what already ships: loop.yaml, the spec's example and every test's args schema still lint. task 1
  4. An if marked started too early: a stop, arming again, an edit and a restart while it probes. task 2
  5. A fold hiding what needs someone: a failure, a question or a note folded away. task 4
  6. A recipe that lints and still does harm: a merge with no person's gate, a value quoted into a command, a check that passes with no CI at all. task 7

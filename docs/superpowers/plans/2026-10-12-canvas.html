The canvas: implementation plan

The work for issue #347: any artifact or sent file docks as a pane beside the transcript; a session's panes form its canvas, columns of stacked panes in one or more browser windows, stored as a layout record; a file re-sent from the same path updates its pane in place; the agent arranges the canvas with dock=, layout_read and layout_set.

specdocs/superpowers/specs/2026-10-12-canvas-docking-design.html. Executors read both. goalA person keeps a page of controls, the document it shapes and the transcript on screen together, across one or two monitors, and the agent can build that arrangement from a prompt. architectureA pure module, layout.py, owns the layout's shape, its validation and the placement grammar. The fold keeps the latest layout record as standing state and trims ended artifacts from it; the session card carries it to browsers. A new client module, canvas.js, draws one window's panes, each absolutely placed in one container so a rearrangement never moves an iframe in the DOM (which would reload the page). A pane reuses the viewer's drawing. stackPython 3.13, pydantic op params, the plain ES-module client, pytest with the fake claude over the real /mcp, Playwright for the browser tests. branchcanvas-dock in the worktree repos/aegis/.claude/worktrees/canvas-dock, which already carries the spec. The PR for #347 is opened from it.

Global constraints

  • Use uv, never pip. Add no dependency.
  • Limits, verbatim from the spec: at most 4 columns in a window, 3 panes in a column and 4 windows. A column is at least 280 px wide, the transcript's column at least 360 px; a pane at least 120 px high. Below the minimums a window draws as tabs.
  • The transcript appears exactly once, in window 1. Window numbers are stable: a new window takes one more than the highest in use; an emptied window is dropped without renumbering.
  • A file's key is f- plus the first 12 hex digits of the SHA-256 of its resolved source path; a record without a source keys as f-<file_id>. The source path never reaches a browser.
  • A page runs in one place: while an artifact is in a pane or the viewer, its card holds a line and no frame.
  • New subsystems add operations and channels, never a protocol field.
  • Client: no <select> or <datalist> (use <pick-chip>), no confirm/alert/prompt, no document or window key listener outside keys.js, every CSS rule scoped #a2 and reading only theme variables, and make site-css after any base.css change.
  • A test that runs over 3 s without @pytest.mark.slow fails the fast lane. Browser tests are pytest.mark.browser and slow.
  • Commits: conventional, English, one logical change, git commit -- <paths>, never amend, never git add -A. Nothing personal in this public repo.
  • Prose in docs, docstrings, help pages and the changelog follows the workspace's unslop rules.
  • A changelog fragment that adds a feature names its help page (a rift rule): task 17's fragment links help/transcript.md.

Where this plan departs from the spec

  • The person's operations are moves, not a whole layout. The spec names one person op, layout.set. A drag computed in the browser against a layout the agent changed a moment ago would overwrite the agent's change. So the browser sends what it did, layout.dock(pane, where), layout.undock(pane) and layout.resize(n, widths, heights), and the server applies it to the current layout with the same place the agent's dock= uses. The agent keeps layout_set.
  • The window route is #w=<n>:<key>, not #/s/<log_id>/w/<n>: the client's routes are #s=<key>, #read=<key> and so on (app.js, route()), and a key can name a linked server's session.
  • A tab switch rebuilds the panes, as the viewer rebuilds its item today (viewer.js, show()). The spec said frames are kept across a switch; that would keep every session's frames alive in hidden tabs. A page re-initialises from the server's state, as a remounted card does.
  • standing.layout is null until the first layout record, and null means the default canvas (window 1, the transcript alone). Old stores fold unchanged.
  • Open on a docked artifact flashes its pane instead of opening the viewer, so the viewer and a pane never hold one page at once.
  • A layout record does not count as activity (Session._record), like a page's state write: dragging a pane must not reorder the Fleet.

Task 17 updates the spec page to match.

Review focus

Inputs the spec implies and no feature test reaches by accident. Each line has its test in the task named.

  • The agent docks while the person drags. Both changes must survive: the person's drop applies to the layout as it is when it arrives. Task 5 tests a person's dock after an agent's layout_set keeps the agent's pane.
  • The same file sent by a relative path and by its absolute path is one file with two versions, not two files. Task 9.
  • A restart. The canvas after a restart of aegis is the canvas before it, including a trim made by a submit. Task 5.
  • A file sent before this change (a record with no source) can still dock, and never updates. Task 9.
  • A pane whose entry the browser does not have yet (the layout arrives on sessions before the transcript snapshot) draws "loading" and fills in when the entry arrives, without an error. Task 7.

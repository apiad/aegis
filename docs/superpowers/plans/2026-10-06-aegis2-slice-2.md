# aegis2 slice 2 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status: tasks 1 to 6 done, task 7 in review, 2026-10-06.** Executed inline by the session that wrote it,
as Alex asked for slice 1.

**Goal:** many sessions on one aegis2 server, shared tabs ordered per browser, the
Fleet view, lazy resume after a restart, Stop, Close to an archive, Reopen, rename.

**Architecture:** A registry owns every session on the server and boots from small
meta files. A session exists without a process; the first prompt after a stop or a
restart starts `claude --resume`. The `sessions` channel replaces `session`.

**Tech Stack:** as slice 1. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-06-aegis2-slice-2-design.md`

## Global Constraints

- Everything from slice 1's plan still holds (no `aegis` imports, no `Path.cwd()`
  below the CLI, `html: false`, token and Origin checks).
- Meta files are written by write-then-rename, at most once per second per session
  during a turn, and always at a turn's end, on stop, close and shutdown.
- Boot reads only meta files; a broken one is rebuilt from its store and never
  fatal.
- Handles: 2 or 3 lowercase alphanumeric segments, hyphen-joined, starting with a
  letter, unique across every session including archived ones.
- Titles: first line of the first prompt cut at 60 characters by default; at most
  120 characters.
- `archive.list` limit defaults to 50, at most 200.
- The protocol version stays 1.

## Review Focus

1. Two browsers, one closes a session: the other's tab disappears and its focused
   view falls back to Fleet. Tested in Task 5.
2. A prompt to a stopped session whose `claude` binary is gone: an error reply and
   the session stays stopped, not half-started. Tested in Task 2.
3. A restart while a session is working: it comes back stopped with the
   "server stopped during a turn" entry, once, not on every later boot. Tested in
   Task 3.
4. Hundreds of archived sessions: boot reads only meta files and the archive pages.
   Tested in Task 3 and measured in Task 6.
5. A tab order in storage naming sessions that are gone, and new sessions missing
   from it: gone ids dropped, new ones appended. Tested in Task 5.

### Task 2: A session without a process

- [x] Tests: stop then send resumes with `--resume` and `/recall` returns the first prompt; the store is the same file and the patches add up; a child that exits leaves the session `stopped` and the next send resumes; a missing binary on resume replies an error and leaves it `stopped`; interrupt on a stopped session is a no-op; `activity()` for a running tool and for prose.

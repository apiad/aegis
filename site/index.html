A programmable multi‑agent meta‑harness.

aegis runs the coding agents you already pay for, Claude Code and OpenCode, side by side in one browser workplace. Its agents hand work to each other and wait on each other, on one machine or across several. And when prose is not enough, they write the interface they need into the conversation.

uv tool install aegis-harness
cd ~/your/project
aegis

The last line starts the server and opens it in a browser window. Version 2.3.0 on PyPI, MIT license, Python 3.13 or newer.

  • Meta-harnessIt runs claude and opencode under your own subscriptions. aegis calls no model and holds no API key.
  • Multi-agentAgents hand off work, queue it for workers, watch long jobs and read each other, across linked machines.
  • ProgrammableAn agent writes a page into the transcript, and your clicks come back to it as answers.

Meta-harnessBring your own subscriptions

The agents you already pay for

aegis calls no model. Each session is the vendor's own command-line agent, claude or opencode, running under your account: a Claude plan, OpenCode Go or Zen, or any provider OpenCode reaches. aegis holds no API key, and your prompts go from the CLI to the vendor as they would from a terminal.

Sessions of both harnesses share one tab bar, each with its own model, effort and permission. The panel shows the quota the session spends: this one runs on OpenCode Go, so it shows Go's three windows.

Every subscription's quota, and its pace

The Fleet band reads each subscription you use: Claude's 5-hour and weekly windows, OpenCode Go's 5-hour, weekly and monthly ones. A gauge shows the share spent, a tick for how much of the window has gone, and where it lands at the reset if you keep this pace.

aegis usage turns the transcripts aegis keeps into what the work cost, by month, weekday, session or repo.

Multi-agentAgents that work together

They hand work to each other

Every agent gets aegis's tools over MCP. It hands a task to a queue of workers and hears back when one finishes, starts a monitor on a CI run and ends its turn instead of polling, reads what another session is doing, and gives that session context or an instruction.

Every answer lands in the transcript as a new turn, headed by whoever sent it: a monitor, a queue task or another agent.

Across machines

aegis link add vps https://dev.example makes this server a client of another aegis. The far server's sessions show in your Fleet under its own band, with its host and quota, and in your tab bar with a server tag. You prompt, interrupt and close them from here, and an agent here hands work to one there with peer_handoff(target="brisk-turing@vps").

The link goes one way. The far server can never reach the one that linked it, so a shared box cannot touch your laptop.

ProgrammableAgents that write their own interface

A page instead of a paragraph

When a reply in prose would lose its structure, the agent writes a page. artifact_create gives it a working skeleton, the agent edits the HTML, and artifact_send runs the page in a hidden frame in your browser before you see it. A page that throws goes back to the agent with the error, so you only ever see one that starts.

Pick a layout in the window.

The page answers the agent

You click, drag, pick or type, and the page sends the result back. A submit wakes the agent and folds the page to one line. An event wakes it and leaves the page live. A state write waits until the agent reads it. The agent can push new state or a new version into a live page.

Today a page lives for one exchange and stays in the transcript as a record. Next, agents keep the pages they write and dock them beside the transcript, so the workplace grows with what its agents build.

The workplaceEverything around it

A Fleet that says who needs you

Each tab and card carries one of six marks: working, needs you, error, review, waiting or done. The Fleet puts the sessions that block on you first, oldest wait on top, and Alt+J goes to the one that has waited longest. Each card shows the plan as a bar with an estimate of the work left.

Fold the work, keep the conversation

z folds each stretch of tool calls and notes between two messages into one line that says what it holds. Press it again and only your messages and the agent's replies remain. Open a line to see that stretch alone.

Press the fold button over the message box, or a folded line.

A panel that stays out of the way

The session panel keeps one compact row per section: the session, the plan with each step's time, the monitors, usage and the host. Hovering a row opens its details beside the panel. Alt+B collapses it, and its edge drags to the width you want.

Hover the panel's rows, drag its edge, or press the panel button in the top bar.

One tap to answer

An agent ends each turn by saying how it ended and may offer up to three replies, which you send with one tap. /model, /effort and /permission switch a running session, and / opens a menu that completes aegis's commands and the agent's own. Alt+M dictates into the box, transcribed in the browser.

Three themes

Ink is the warm dark palette of the terminal app aegis used to be. Logbook is a daylight lab notebook with times in the margin. Syalia is the house design system, with tool calls as chips.

Press the theme in the window's top bar.

On a phone

Below 760 px the tabs get their own row, the panel becomes a drawer, and touch targets are 44 px. Chrome installs aegis as an app named after the server. A return to a recent tab, or a reconnect after the phone slept, sends only what changed.

One file configures it

aegis reads .aegis.yaml from the nearest ancestor that has one. An agent is a preset of harness, model, effort and permission, and a queue names the agent its workers run as and how many run at once. A new tab starts from a preset and can change any field for that session. aegis init writes a first file from the harnesses installed on the machine, aegis doctor names every problem by its place in the file, and the server follows the file as it changes.

default_agent: opus
agents:
  opus: {harness: claude-code, model: opus, effort: high, permission: full}
  deepseek: {harness: opencode, model: opencode-go/deepseek-v4-pro, effort: high, permission: write}
  reviewer:
    harness: claude-code
    model: opus
    effort: max
    permission: read
    priming: |
      You review changes for correctness and report findings by severity.
queues:
  general: {agent: opus, max_parallel: 5}
recap: {agent: opus}

Permission is read for plan mode, write to accept edits, auto, or full to bypass permissions. An OpenCode agent names its model as provider/model. The optional recap names the agent that writes a two-sentence recap when you come back to a tab after a while.

What an agent can call

Every session's harness connects to /mcp with its own token, so no tool asks who is calling. The tools are named mcp__aegis__<verb>.

Working together

peer_handoff
Give another session context or an instruction, here or on a linked server (handle@server). It arrives as a new turn.
peer_read
The last entries of another session's transcript, one line each.
session_list
The open sessions on this server.
session_spawn
Start a session from an agent preset, with at most your own permission.
queue_enqueue
Hand a self-contained task to a fresh worker on a queue. The result arrives as a turn when the worker finishes.
task_status, task_cancel, task_resume
Follow a task, cancel it, or put its worker back to work with its conversation intact.
monitor_start, monitor_list, monitor_cancel
Watch a long process with bash conditions, and be woken when one holds, fails or times out.

Talking to you

artifact_create, artifact_send
Write a page from a working skeleton and put it in the transcript once it starts in your browser.
artifact_read, artifact_update, artifact_close
Read what the page kept, push new state or a new version into it, or take it back.
turn_end
Say how the turn ended and offer up to three replies. It sets the mark on the tab and the line on the card.
plan_update
Keep the plan where you can see it, timed per step, on the card and in the panel.
file_send
Hand you a file: a card with a preview, Open and Download.

Knowing where it runs

agents_list
The presets it can spawn.
quota_read
How much of each subscription window is left, per provider.
config_doctor
Check .aegis.yaml, the harnesses it names and the state directory.
session_rename, meta
Name its own session, and read how aegis works for it.

Where it runs

aegis serve listens on loopback at port 8742 and prints a URL with a token. Opening it once signs that browser in: the token moves into an HttpOnly cookie that lasts a year. aegis serve -d detaches and outlives the terminal or the SSH connection. Behind a reverse proxy, --origin https://dev.example names the public origin, and the proxy terminates TLS. Agents reach /mcp on loopback, so do not proxy it. A restart brings sessions back stopped, and the next prompt resumes each one.

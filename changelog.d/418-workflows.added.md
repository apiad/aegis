- **Workflows.** An agent can write a piece of work as a workflow: a tree in which every node says what it does. The person approves it from a card in the transcript, the server runs each step as a locked session, and the card tells what happened. It runs steps in sequence or side by side, maps a step over a list, and keeps the server under a pool of agents (`workflows: {max_agents}`), in total and per agent. Workflows now run shell commands, checks that wait on a command, an expression or a judging agent, pauses, branches and loops, with deadlines, retries, reusable blocks and named result schemas; a server restart never runs a command twice, and agents are told when to reach for a workflow. The lint refuses a `{{...}}` written inside shell quotes, where its quoting would come undone, and the card says how often each command runs: once, for each item, or each round. A failed step no longer fails the run: it waits for the main agent, which retries it, skips it, changes it or ends the run; workflows stop at gates for the main agent or the person, workers ask the main agent questions, the main agent writes notes into the story, a running workflow changes only through a diff the person approves on a card, a stopped run can be armed again keeping what ran, and a step can run in the main agent's own session.
